# Ether v0.3.22

Highlights:

- **Live TV catch-up.** When your IPTV provider keeps an archive (Xtream `tv_archive`, M3U `catchup`), programmes that already aired play from the guide in Vela. They also appear in a new **Catch-up** library in Plex, Jellyfin, Emby and Silo, so last night's news is one click away in any app (#812, thanks @kraigeisenman).
- **Rewind live TV.** Every live IPTV channel keeps a rolling rewind window while someone is watching (60 minutes by default). In Vela you can pause, rewind, start the current programme over and jump back to live.
- **What's new after every update.** Ether shows the release notes in the console the first time you open it after an update, so you don't have to look them up on GitHub.
- **Faster Vela library collections** on large libraries: one page went from thousands of database statements to about twenty (#814, thanks @krakenn9).

## Live TV

- **Catch-up:**
  - **Detection:** archive windows are read during the normal source refresh, from Xtream `tv_archive` / `tv_archive_duration` and from M3U `catchup`, `catchup-days` and `catchup-source`. A channel loses catch-up when its provider stops reporting it.
  - **Playback:** a programme inside the archive plays as a normal, seekable title. It counts as one stream for the viewer and one connection to the provider, like live TV.
  - **Catch-up library:** Plex sees a TV section, with one show per programme and the airings as dated episodes. Jellyfin and Emby see Series and Episodes, and Silo sees the same library. Airings leave the library as they age out of the provider's archive.
  - **Channel badge:** channels with an archive show a **Catch-up: N days** badge in the console.
  - **Xtream:** Ether's own Xtream output now reports `tv_archive` and plays archived programmes, so Xtream apps get catch-up through Ether too.
- **Rewind:**
  - **Live TV › Settings** has one setting, "Rewind live TV up to N minutes" (0 to 240, default 60; 0 keeps live only).
  - The window only exists while a channel is being watched, and it stays within the transcode cache's disk budget. A full disk shortens the oldest windows instead of stopping playback.
  - A channel's own rewind length still takes precedence.
  - In Vela, a paused live channel keeps your place. **Live** jumps back to the live edge, and seeking outside the window says so instead of guessing.

## Console

- **What's new:**
  - **When it shows:** after any update (automatic, installer, package or Docker), a drawer shows that version's release notes, built into Ether. Dismiss it once; it remembers.
  - **Updates page:** **Maintenance › Updates** reopens the installed version's notes, and an available update's notes show before you install it.
- **Update checks** no longer run every time you open Maintenance › Updates. The page shows when Ether last checked and when it checks next, and **Check now** checks on demand.

## Playback and apps

- **Jellyfin for Roku** no longer exits to Roku Home when you open a film or episode whose tracks Ether hasn't read yet. Episodes always carry their series, and the encoding settings endpoint answers like Jellyfin (#421, thanks @krakenn9).
- **Dolby Vision on Vela:** when Vela says the display has no Dolby Vision, or an owner rule turns it off, Ether no longer sends a Dolby Vision stream:
  - profile 5 converts;
  - profile 8.1 plays its HDR10 base layer.

  The same rules now apply when the original file plays directly (#810, thanks @theatarr).
- **Silo and on-demand Usenet:** a start whose release turns out unreadable partway through fails over to another release, instead of ending playback (#806, thanks @red4711).
- **Plex play queues** and pre-play details no longer wait for a whole source search before answering.
- **Vela Home:** a cached Home no longer lists a row that "See all" would refuse, so it can't loop on "Try again".

## Releases

- **A release named only "The.S01E03…"** (a show name cut down to an article) no longer counts as another show just because an indexer tagged it with that show's IDs. The same applies to other names that are only articles, or only the first word of the wanted title. Titles that differ only by a year or country, like "Doctor Who (2005)", still match.

## Plugins and the SDK

- **Watch sync for plugins** (#813, thanks @b4skyx):
  - `viewers.setWatchState` now works, marking a plugin's own items or catalogue titles watched or unwatched.
  - Watch events say what changed, why (playback, a manual mark, a plugin or an import), and which item: the plugin's own item reference, or catalogue IDs with season and episode.
  - A plugin's own writes are not echoed back to it.
- **`kinds.browse` filters** (#807, thanks @FizzWhirl):
  - `empty` selects items with no value in a field, or with any value;
  - an `anyGroups` group can match across fields ("label or parent label");
  - `excludeQuery` drops items whose text matches.
- **Faster multi-facet browses** (#808, thanks @FizzWhirl): a browse with several facets now starts from its narrowest one, for both the page and its count. On a 200,000-item kind it went from about 600 ms to 8 ms on SQLite, and from 216 ms to 13 ms on PostgreSQL.

## Performance

- **Vela library collections** batch their counts, membership and artwork reads, so a page costs about the same whatever the number of collections (#814).
- **Person pages** no longer wait on database writes while the server is busy (#814).

## Upgrade notes

- **Catch-up** appears on its own wherever a source reports an archive; there's nothing to turn on. It needs the provider to keep an archive for the channel.
- **Rewind** uses disk space while a channel is being watched, about 3 GB per viewer-hour at typical bitrates, within the existing transcode cache budget. Set it to 0 under Live TV › Settings to keep live only.
- **Update checks** on the Updates page are now on demand; Ether still checks on its own schedule.
- **Vela 0.2.69** or later is recommended.
